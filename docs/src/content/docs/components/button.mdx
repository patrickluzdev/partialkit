## Variants

| Class | Use |
| --- | --- |
| `.btn` | Primary action — the default variant, applied when no other is |
| `.btn-secondary` | Secondary action |
| `.btn-outline` | Bordered, sitting on the page surface |
| `.btn-ghost` | No border, no background until hovered |
| `.btn-destructive` | Irreversible action — a wash of the danger colour, not a solid fill |
| `.btn-link` | Looks like a link, behaves like a button |

## Sizes

<Preview src="button/sizes" layout="row" />

| Class | Height |
| --- | --- |
| `.btn-xs` | 24px |
| `.btn-sm` | 28px |
| `.btn` | 32px |
| `.btn-lg` | 36px |
| `.btn-icon-xs` `.btn-icon-sm` `.btn-icon` `.btn-icon-lg` | Square, matching the text size of the same name |

An icon-only button needs an `aria-label` or `.sr-only` text — there is no visible text to name it.
Composing the sizes (`.btn-icon.btn-sm`) reaches the same place, for markup already written that way.

## States

<Preview src="button/states" layout="row" />

Any element takes the classes, but reach for a real `<button>` or `<a>` so keyboard activation,
focus order and `disabled` come from the platform.

## With an icon

An `svg` child is sized and made non-interactive automatically. Mark it with
`data-icon="inline-start"` or `data-icon="inline-end"` so the padding tightens on that side.
