| Class | Part |
| --- | --- |
| `.field` | One label, control and its help text |
| `.field-group` | Several fields stacked with wider spacing |
| `.field-description` | Help text |
| `.field-error` | Validation message |
| `.field-set` | A semantic `<fieldset>` with the same spacing |
| `.field-legend` | Its `<legend>`; `data-variant="legend"` or `"label"` sizes it |
| `.field-content` | Groups control and description when the label sits beside them |
| `.field-title` | Title with label styling inside `.field-content` |
| `.field-separator` | Divider between groups |

## Error state

Set `aria-invalid` on the control. The border and ring follow, so a server-rendered error needs no
extra class — and screen readers get the state from the same attribute.

<Preview src="field/error-state" width="sm" />

Point `aria-describedby` at the error so it is announced with the control.

## Orientation

`data-orientation="horizontal"` puts the label beside the control. `"responsive"` starts stacked and
switches at the container's width — a container query, so it reacts to its own column rather than the
viewport, which needs a `.field-group` around it.

<Preview src="field/orientation" layout="stack" />

## Fieldsets

<Preview src="field/fieldsets" width="sm" />

`data-invalid` on the `.field` marks the whole block, so the label turns with the control instead of
each part being styled separately.

## Disabled

A disabled control dims its own label, read from the control's state rather than a marker class.
